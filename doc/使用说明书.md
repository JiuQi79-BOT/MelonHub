# MelonHub 项目使用说明书

本文说明项目的用途、启停方式、控制台各页面的功能以及从零建立一条授权链的步骤。接口细节见 [接口说明](API.md)，技术分层、缓存与权限规则见 [架构说明](ARCHITECTURE.md)。

当前本机已按用户选择复用 Docker MySQL，具体环境与配置见 [本地 Docker 运行说明](本地Docker运行.md)。

## 一、项目解决什么问题

MelonHub 是企业内部统一权限平台，为 20 多个业务软件提供一致的角色、权限配置和在线授权判断。平台回答的是“某用户在某部门、某软件中有没有指定权限”，具体业务操作仍由业务软件执行。

例如，同一位用户在研发部门的项目系统中可以创建项目，在产品部门的同一系统中只能查看项目。两个部门即使都有名为“负责人”的角色，角色关联和权限也各自独立。

本项目严格使用 RBAC0：

```text
用户 ──分配──> 角色 ──关联──> 权限
          所有角色和权限均属于某个“部门 × 软件”授权域
```

用户可以拥有多个角色，角色可以关联多个权限；有效权限取并集。用户不能直接获得权限，没有角色继承、通配权限或额外业务规则。角色分配可以设置有效期，到期后自动不再生效。

在此之上，平台提供授权治理能力：员工通过业务系统申请角色、管理员审批；定期发起权限复核并回收不再需要的授权；授权变更时通过签名 Webhook 通知业务系统。

## 二、运行组成与准备工作

| 组成 | 运行位置 | 作用 |
| --- | --- | --- |
| 管理控制台（Vue 3 + Ant Design Vue 4） | 本机，固定 5174 | 管理配置、审批与复核、诊断授权、查看审计、接入联调 |
| Spring Boot 后端 | 本机，8080；监控端口 8081 | 管理 API、凭据认证、在线权限判断、Webhook 投递 |
| MySQL | 当前为已有本机 Docker 容器；也支持 cloud | 唯一数据源：配置、授权关联、上下文、审批复核、Webhook 队列和审计 |
| Redis | 本项目专用容器 `melonhub-redis`，`127.0.0.1:6380` | 权限缓存与全局限流计数，可随时清空；不可用时自动回退 MySQL 与实例内限流 |
| Java SDK（可选） | 业务软件后端 | `sdk/java` 中的 `melonhub-client`，封装接入细节 |

前端通过本机 `/api` 代理请求后端，后端通过 TLS 连接所选 MySQL。当前 local 模式复用 `xmudemo-mysql`，需要 Docker Desktop 运行。选择 cloud 时需云服务器已开机、MySQL 与网络可用；启停脚本不负责开关 ECS、部署 Swarm 或重启云端数据库。

本机需要 JDK（源码目标 Java 17）、Maven、Node.js/npm、Docker Desktop 和 PowerShell。现有本机环境已具备这些工具。

根目录 `.env` 保存真实数据库地址、数据库凭据、Redis 密码和初始管理员账号。新环境从 `.env.example` 补齐配置，不要把真实凭据写进 README、说明书、截图或命令参数。

| 关键配置 | 要求 |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | `local` 或 `cloud`，当前为 `local` |
| `LOCAL_DB_HOST/PORT/NAME/USERNAME/PASSWORD` | 本机回环入口、固定 `melonhub_rbac` 及已有数据库凭据 |
| `LOCAL_DB_CONTAINER` | 可选，允许启动的已有 MySQL 容器名称 |
| `CLOUD_DB_*` | 云端入口，库名固定 `melonhub_rbac` |
| `ADMIN_USERNAME/ADMIN_PASSWORD` | 初始超级管理员，只在账号不存在时创建；密码 12–100 个字符且 UTF-8 编码不超过 72 字节，超过时拒绝启动 |
| `ADMIN_PASSWORD_RESET` | 平时为 `false`；忘记初始管理员密码时临时设为 `true` 重启一次 |
| `CACHE_ENABLED` | `true` 启用 Redis 权限缓存；`false` 完全关闭 |
| `REDIS_HOST/PORT/PASSWORD/DATABASE/CONTAINER` | 专用 Redis 的地址、端口 6380、密码（自行生成的随机长字符串）与容器名 |
| `SERVER_PORT` | `8080`，与前端代理保持一致 |
| `SEED_DEMO` | `false`，不自动生成演示数据 |
| `TEST_DB_TARGET`、`TEST_DB_*` | 测试入口及独立测试库 `melonhub_rbac_test` |

可选调优项在 `.env.example` 中以注释形式给出默认值：`APP_RATE_LIMIT`（每软件每秒 1000 次）、`DB_POOL_SIZE`（20）、`AUDIT_RETENTION_DAYS`（180）、`ADMIN_IDLE_MINUTES`（30）、`MANAGEMENT_PORT`（8081）、`GLOBAL_RATE_LIMIT`（`true`，经 Redis 跨实例共享限流额度）、`WEBHOOK_DELIVERY_ENABLED`（`true`，本实例是否推送 Webhook）、`WEBHOOK_RETENTION_DAYS`（30）。启用时去掉行首 `#` 并填写数值，不要保留 `KEY=` 这样的空值。

## 三、一键启动和停止

### 3.1 双击启动

双击根目录的 `start-all.cmd`。脚本会读取配置，按需拉起 MySQL 容器、创建或拉起专用 Redis 容器、构建后端、安装缺失的前端依赖，然后在后台启动前后端，等待后端、数据库与前端代理均健康后打开浏览器。

固定访问 `http://127.0.0.1:5174`。5174 或后端 8080 被其他程序占用时会报错，不会停止该程序或自动切换端口。5173 留给其他项目使用。

已运行且健康的项目进程会被复用，重复双击不会再开一套服务。修改代码或配置后，应先停止再启动，使新内容生效。

命令行也可以运行：

```powershell
./scripts/start-all.ps1
./scripts/start-all.ps1 -NoBrowser
./scripts/start-all.ps1 -Rebuild
```

`-NoBrowser` 只启动并检查服务，不自动打开页面；`-Rebuild` 强制重新打包后端，使用前先停止正在运行的后端。启动成功会把实际地址记录在忽略文件 `.local/services.json`。

### 3.2 双击停止

双击根目录 `stop-all.cmd`，或执行：

```powershell
./scripts/stop-all.ps1
```

停止脚本按本项目绝对路径识别 JAR、Vite 和可识别的 IDEA 后端进程，并停止带有 `com.melonhub.role=cache` 标签的专用 Redis 容器。它不会停止共享 MySQL、云端数据库、其他容器或其他 Java/Node 进程。重复停止是安全的。

IDEA 若通过不含项目路径的临时参数文件运行，脚本可能无法确认归属；此时应在 IDEA Run/Debug 面板停止该进程。

关闭网页不会停止服务。后台日志在 `.local/logs/backend.log` 和 `.local/logs/frontend.log`，启动器会屏蔽已配置的密码和服务器地址；分享日志前仍需核对内容。

### 3.3 数据库与缓存连接

启动后端时，Hikari 连接池建立到所选 MySQL 的连接，平时保持至少 5 条，高峰最多 20 条（`DB_POOL_SIZE`）。停止后端时这些连接全部释放，不会删除数据或关闭数据库服务。旧版本连接池固定为 10 条时，曾在云端实测“启动后 10 条 → 停止后 0 条 → 重启后 10 条”。

Redis 容器不做持久化，停止或重建后缓存与限流计数为空，服务会从 MySQL 重新计算，结果不受影响。

### 3.4 在 IDEA 中调试

1. 在 IDEA 打开项目根目录并导入根 `pom.xml`。
2. SDK 选择本机 Java 17 或兼容版本；当前实测路径为 `C:\Program Files\Java\jdk-17`。
3. 先用一键脚本或 Docker Desktop 确保 MySQL 与 Redis 容器在运行。
4. 选择 `MelonHub Backend` 启动/调试后端，选择 `MelonHub Frontend` 启动 Vite；支持 npm 的 IDEA 可以用 `MelonHub Stack` 同时启动；`MelonHub Tests` 执行所选入口的独立库测试。
5. 在 Run/Debug 面板管理停止和重启。切换运行方式前先停止旧实例，避免 8080 冲突。

共享配置位于 `.run/`。本轮实际服务启停验证使用一键脚本完成，没有验证 IDEA 图形界面启动按钮。Java SDK 是独立的 Maven 工程，需要时在 IDEA 中单独导入 `sdk/java/pom.xml`。

## 四、登录、角色与界面布局

使用 `.env` 中的初始管理员账号登录，它是超级管理员。之后可以在“管理员账号”页为其他人创建账号。

| 管理员角色 | 能做什么 |
| --- | --- |
| 超级管理员 | 全部功能，并管理管理员账号（含解锁、重置两步验证） |
| 平台管理员 | 维护部门、用户（含批量导入）、软件（含限流）、API Key、Webhook 和全部授权域 |
| 软件管理员 | 只看到被授权的软件，管理这些软件的角色、权限、用户授权、审批、复核、清单、API Key 和 Webhook；部门与用户只读 |
| 审计员 | 所有页面只读，可以导出审计、校验审计链 |

没有修改权限时，页面会隐藏新建、编辑按钮并显示只读提示；直接调用接口也会被拒绝。

会话最长 8 小时，空闲 30 分钟自动退出。连续 5 次密码或动态口令错误锁定 15 分钟，超级管理员可提前解锁。关闭浏览器标签页后需要重新登录。

密码长度为 12–100 个字符，且不能超过 72 字节（UTF-8 编码，约 24 个汉字；英文字母和数字每个 1 字节）。登录过程中如果账号恰好被改密、重置、改角色、停用或调整两步验证，登录会提示“账号凭据已变更，请重新登录”，重新登录即可。

**两步验证**：右上角账号菜单的“两步验证”可绑定手机认证器应用（标准 TOTP，6 位、30 秒）。按提示输入密钥，再填入认证器上的动态口令确认后生效。启用后登录时，输入密码后还需输入动态口令；同一个口令登录成功后不能再次使用。停用需要输入当前密码和动态口令。启用、停用或重置都会结束该账号的已有会话，需重新登录。手机丢失时请超级管理员在“管理员账号”中重置。账号菜单中还有“修改密码”。

界面左侧是导航菜单，分为“组织与软件”“授权治理”“安全与审计”“开发接入”四组，可收起。日常配置从部门或软件列表进入：点击名称，打开该对象的配置抽屉，在“成员授权、角色、权限项、部门成员”之间切换，具体编辑使用弹窗或成员抽屉。角色、权限、用户授权不再占用三个侧栏入口，旧页面地址仍可访问。

顶部依次是面包屑、全局搜索、授权域选择（概览及旧授权页面）、服务状态、明暗主题切换和账号菜单。配置抽屉使用自己的部门或软件选择，不改变外层页面的授权域。全局搜索的部门、软件和角色结果也会打开对应配置抽屉。审批中心与权限复核使用页内的软件筛选，结果包含所选软件的各部门记录。

- **全局搜索**：按 `Ctrl+K`（macOS 为 `⌘+K`）聚焦，输入姓名、外部标识、编码或名称，可直接跳到对应的用户、部门、软件或角色。
- **明暗主题**：默认跟随操作系统；点击切换后，选择保存在本浏览器中。

服务状态每 30 秒刷新：绿色“服务正常”；黄色“缓存降级”表示 Redis 不可用或恢复中，授权判断改走数据库，结果仍然正确但响应变慢；红色“数据库不可用”需要立即处理。

**在手机上使用**（屏幕宽度 768px 及以下）：点左上角菜单按钮打开导航；需要授权域的页面在顶栏下方整行显示“部门 × 软件”选择；放大镜图标展开全局搜索。列表每一行显示为一张卡片，左侧是字段名，空字段不显示，底部是操作链接；详情抽屉铺满屏幕。审计日志默认只显示关键字筛选，点“更多筛选”展开时间、操作、操作人等条件。服务正常时手机顶栏不显示状态，出现降级或故障时才显示。

## 五、两种“切换部门”的区别

概览顶部或配置抽屉中的“部门 × 软件”选择的是**管理界面的授权域**，决定角色、权限及分配关系的查看和编辑范围。它只影响你自己的界面，不会改变任何业务用户的状态。选定部门后只需选软件，选定软件后只需选部门；抽屉中各页签沿用同一范围。

业务用户真正的部门切换发生在业务系统创建权限上下文时（`POST /api/v1/contexts`），或在“接入指南 → 在线调试”中创建上下文时。同一用户切换到其他部门后，其原部门在所有软件、所有设备中的旧上下文都会失效，切回也不会恢复。

只想查看某用户在某部门能得到什么权限而不想切换其部门，请使用“权限诊断”。

## 六、各页面的功能

### 6.1 概览

展示平台规模（接入软件、部门、用户、近 24 小时操作数）和当前授权域的统计（角色、权限、已授权用户、部门成员、有效 API Key、有效权限上下文），以及待办事项（如 7 天内到期的授权，可点击进入“用户授权 → 即将到期”）和服务状态。最近 8 条操作在页面底部整行显示，每条一行（时间、操作、对象与详情、操作人），完整记录见“审计日志”。没有有效 API Key 的软件会以黄色提示列出，因为它们无法调用权限接口。

### 6.2 部门

维护组织部门名称与唯一编码，查看成员数。点击部门名称或“软件与授权”打开配置抽屉。新建部门后直接进入“部门成员”，可以新建用户（默认加入该部门），也可以“添加已有用户”，检查资料并保存后保留原有部门归属。

在抽屉中选择软件，即可维护该域的角色、权限和成员授权。“批量配置软件”可选择一个来源部门及多个软件，一次补齐这些软件在当前部门的角色、权限配置。每个软件独立提交，结果逐项显示；遇到失败保留已完成项，剩余项可以继续处理。

部门是权限隔离的一个维度，不是角色继承层级。创建部门不会自动创建角色、权限或成员。这里的“配置软件”只选择部门与软件的授权域，没有新增软件准入开关；复制是一次性补充，不是持续同步模板。

仍有成员、角色或权限时不能删除部门，提示会写明还剩什么，例如“部门下还有 1 名成员、1 个角色、1 个权限，请先移除后再删除”。前成员遗留的权限上下文会在删除时一并清除。

### 6.3 用户

按姓名、外部标识、邮箱搜索，按部门和启用状态筛选，分页浏览。每个用户维护姓名、外部标识 `externalId`、可选邮箱和所属部门（可多选）。外部标识必须与业务系统认证后的用户 ID 一致。

- **授权详情**：抽屉中按“部门 × 软件”列出该用户的全部角色和有效权限，以及当前有效的上下文。可以“强制下线”，使其全部上下文立即失效。
- **编辑**：修改外部标识时会提示原有上下文全部失效；移出部门时会提示该用户在这些部门的角色分配被一并删除。
- **停用 / 启用、删除**：停用后其上下文立即失效，重新启用也需要业务系统重新创建上下文。
- **批量导入**（超级/平台管理员）：在弹窗中粘贴 JSON 格式的用户列表（姓名、外部标识、邮箱、部门编码，格式见输入框中的示例），每次最多 500 行。按外部标识新建或更新用户，按部门编码补齐成员关系，不会移除已有成员关系，也不分配角色。导入逐行处理，每行单独校验，某行缺少字段、超长或部门编码不存在只让该行失败，不影响其他行，结果列出失败的行号和原因。已存在用户的外部标识不会被导入改写。

加入部门只获得成员身份，不会自动获得任何权限。总表先筛选部门，再点击“为所选部门批量授权”打开该部门的配置抽屉；单人可直接点击“分配角色”，沿用筛选的部门。部门抽屉中的“部门成员”页签则直接在当前范围内操作。

部门、用户、软件、角色、权限列表均可“导出 CSV”，按当前筛选导出全部匹配行，不限于当前页。软件列表还可按启用、停用状态筛选。

### 6.4 软件接入

一个“软件”表示一个独立接入的业务系统。创建时填写名称、唯一编码、负责人和描述，系统会生成一个默认 API Key 并**只显示一次**，交给该软件的可信后端保存。

保存一次性 API Key 并关闭提示后，直接进入软件配置抽屉。点击软件名称或“部门与授权”也可打开：选择部门，创建角色并配置权限，随后分配成员。“复制到多个部门”可把当前来源部门的配置一次补齐到多个目标部门，已有同编码配置保持不变，不复制成员授权。

每行还有“API Key”“Webhook”入口，“更多”菜单中有限流、启停和删除。

点击“API Key”打开密钥抽屉：

- **新建密钥**：填写名称和有效期（或永不过期）。每个软件最多 10 个有效密钥。
- **吊销**：使用该密钥的请求立即失败。
- **紧急轮换**：一次吊销全部旧密钥并生成一个新密钥，适合怀疑泄露时使用。
- 列表显示每个密钥的前缀、状态、创建人、过期时间和最近使用时间（约每分钟更新）。

计划内更换密钥时，先新建密钥并在业务后端替换，等旧密钥的“最近使用”时间不再变化后再吊销它，可以不停机完成轮换。

点击“Webhook”打开通知抽屉：登记接收地址（`http://` 或 `https://`）、订阅的事件（或全部），签名密钥可自定义，留空则自动生成并**只显示一次**。可以编辑、删除、发送测试事件，以及查看投递记录（状态、尝试次数、最后的 HTTP 状态与错误）。投递失败会自动退避重试，共 8 次。业务后端如何验签见 [接口说明](API.md) 第 3.6 节。

**限流**（超级/平台管理员）：为单个软件设置每秒调用上限，留空恢复平台默认（`APP_RATE_LIMIT`），0 表示不限制。列表“限流”列显示“默认”“不限”或具体数值。修改后最多约 30 秒内在各实例生效。

停用软件会清除其全部上下文并使其密钥暂时不可用。删除软件会删除其密钥、Webhook、管理员授权和上下文；仍有角色或权限时无法删除，提示会写明数量，例如“软件下还有 2 个角色、2 个权限，请先删除，或改为停用”。

### 6.5 角色

在部门或软件配置抽屉的“角色”页签维护当前“部门 × 软件”的角色，用于把一组权限打包给用户。可按名称、编码搜索和按状态筛选。

- **新建与配置权限**：新建角色后直接打开权限弹窗。在穿梭框中从“可选权限”移到“已授予”；缺少权限时可“新建权限并勾选”，无需离开当前角色。保存整体替换该角色的权限集合；“保存并分配成员”接着打开该角色的成员抽屉。
- **成员**：抽屉中查看拥有该角色的用户，可从本部门成员中搜索添加或移除，保存后被调整用户在本域的上下文失效。成员列表加载完成前不能添加、移除或保存；切换到其他角色或关闭抽屉会放弃未保存的修改。如果保存时其他管理员恰好也在调整这些用户的角色，平台会自动重试；仍然冲突时提示稍后再试。
- **停用 / 启用、删除**：停用后下一次校验不再计入该角色权限；删除会移除其分配与权限关联，不删除用户或其他角色。

页头的“清单与复制”下拉菜单：

- **导出本部门清单 / 导出全部部门清单**：把当前部门（或当前软件有配置的全部部门）的权限和角色（含角色权限关系）下载为 JSON 文件，按部门编码分节，便于留档、评审或迁移到其他环境。
- **导入清单**：粘贴清单 JSON，按清单中每节的部门编码，在当前软件的对应部门新建或更新权限与角色。要导入到另一个部门，把该节的 `code` 改成目标部门编码即可；部门编码必须已存在。清单里没有的配置保持不变，导入不会删除任何权限、角色或用户分配。
- **从其他部门复制**：把同一软件下另一个部门的权限和角色（含角色权限关系）复制到当前部门。当前部门已有的同编码权限会复用，同编码角色会跳过，不复制用户分配。适合新部门快速沿用标准配置。

### 6.6 权限

在配置抽屉的“权限项”页签维护权限编码、名称、资源和操作，例如 `order:approve`、“审批订单”、`order`、`approve`。可按编码、名称搜索和按资源筛选，列表显示有多少角色包含该权限。点击“使用者”可以反查哪些用户通过哪些角色持有该权限，以及这些分配的到期时间。同一用户在不同部门持有时分别列出；超过 500 项时只列出前 500 项并提示总数，可按部门筛选后查看。

权限编码区分大小写，平台只把它当作标识，不会根据 `read`、冒号或 resource/action 推导额外权限。业务后端检查的编码必须与这里完全一致。删除仍被角色使用的权限时会提示受影响的角色数。

### 6.7 成员授权

日常分配从部门配置抽屉的“成员授权”开始：勾选成员（可跨页）→ “批量分配软件角色” → 选择一个或多个软件，分别勾选角色并设置新增分配的有效天数 → 追加。已有有效角色及其期限保持不变；未持有或已到期的所选角色按本次设置授予，天数留空为永久。只有授权发生变化的成员在对应域的旧上下文失效。

表格按当前软件显示分配，切换软件保留本部门已勾选成员。批量弹窗按软件逐项提交并显示结果，遇到失败保留已完成软件，剩余软件可继续处理；不会因某个软件失败撤销其他软件已完成的授权。

分页列出当前部门的全部成员及其在当前软件中的角色，可按姓名、外部标识或邮箱搜索。需要为某人移除角色或设置不同期限时，点击该行“个别调整”。保存会替换该用户在本域的完整角色集合，取消勾选表示移除，且使其在本域的旧上下文失效。批量弹窗和个别调整弹窗都提供角色“全选”“清空”。

勾选的每个角色下方都有自己的“到期时间”，留空表示永久，打开弹窗时显示该角色当前的到期时间。可以用“全部设为 N 天后 → 应用”或“全部永久”一次设置所有勾选的角色，再单独调整个别角色。没改动的角色保留原有到期时间；表单打开期间已经到期的角色会提示重新选择期限或取消勾选，不会被自动授为永久。到期时间必须晚于当前时间、不超过 3650 天后。列表中带期限的角色显示“至 MM-DD”，临近到期显示为橙色。

到期的角色立即失效，校验结果从到期时刻起不再包含它们。后台每分钟清理一次已到期的分配，在审计中记为“角色到期”，并向订阅了“用户角色到期”的 Webhook 发送通知。需要提前收回时，请直接取消勾选。

“即将到期”标签列出当前软件在 7、15 或 30 天内到期的角色分配，方便提前续期或确认回收。

用户需先加入该部门才会出现在这里。“管理本部门成员”切换到同一抽屉的“部门成员”页签：“部门成员”维护资料和部门归属，“成员授权”处理多人多软件角色及个别调整，“角色 → 成员”按单个角色查看和维护成员。这些入口修改同一套分配关系。

### 6.8 审批中心

列出业务系统代员工提交的角色申请，可按状态（待审批、已批准、已驳回、已撤回）、软件和关键字筛选，进入时沿用此前选择的软件，之后以本页筛选为准，涵盖该软件的各部门。每条申请显示申请人、部门、角色、理由、期望天数和状态。申请记录保存提交时的姓名、部门和角色名称，之后用户或角色被删除也能看到历史；角色已删除或已停用时在角色旁标注“已删除”或“已停用”。

- **批准**：在“授权期限”中三选一：按申请（申请的天数，未指定则永久）、永久、指定天数（1–3650）。批准后授权立即生效，该用户在该域的旧上下文失效，有期限的授权到期后自动回收。
- **驳回**：可以填写理由，理由会写入审计；业务系统会收到 `access.rejected` 事件，事件中带有驳回理由。

只能处理待审批的申请；角色已停用或已删除、用户已不在该部门时无法批准。同一员工对同一角色同时只能有一条待审批申请。员工在业务系统中可以撤回仍待审批的申请。需要对该软件有写权限才能审批。

### 6.9 权限复核

用于定期确认“谁还应该保留哪些权限”。点击“发起复核”，选择软件、可选的部门和截止天数，系统会对当时仍有效的角色分配拍一份快照。

在复核抽屉中逐条标记“保留”或“回收”并可填写说明；关闭复核前可以随时改标，以最后一次为准。点击“关闭并应用”后，所有标记为回收的分配被立即解除，相关用户在对应域的上下文失效；**仍未决定的条目视为保留**。复核只回收快照时的那一次分配：如果复核期间该角色已被移除、续期、改了期限或重新授予，关闭时不会回收新的授权，该条目显示“已跳过”，关闭结果中注明跳过的数量。抽屉中的统计在打开、每次标记和关闭前都会重新读取。关闭后复核不能再修改，列表保留结论统计供审计；之后删除相关用户、角色或部门，复核记录中仍保留当时的名称。

### 6.10 权限诊断

选择用户、部门、软件，激活角色可选“全部已分配角色”或“指定角色”，再填写待校验权限，点击诊断。诊断只做计算，不创建上下文，也不切换用户的当前部门。修改任何诊断条件都会清空上一次的结果；条件改变前发出、之后才返回的诊断结果会被丢弃，因此显示的结果总是对应当前条件。

结果包括：

- 能否为该用户创建上下文；不能时列出原因，例如用户停用、软件停用、不是部门成员、指定了未分配或已停用的角色。
- 该用户当前所在部门，以及创建上下文是否会切换部门。
- 已分配角色及是否激活，有效权限及授予它的角色。
- 每个待校验权限的允许或拒绝。

用户反馈“没有权限”时，先在这里诊断，通常能直接看到缺少的环节。

### 6.11 审计日志

按时间范围、操作类型、操作人、部门、软件和关键字查询，记录谁在何时做了什么、对象是什么、变更详情和来源 IP。登录失败、账号锁定、密钥轮换、软件停用、强制下线等高风险操作以醒目颜色标出。删除部门或软件的记录以名称为对象，详情中注明编码。

“导出 CSV”按当前筛选条件导出，单次最多 5000 条；超过时会提示缩小范围后分批导出。

“校验链条”重新计算审计哈希链：审计记录写入后约 10 秒会被接入链条，每条记录的哈希包含上一条的哈希。可以填写起始序号和条数，留空为从头校验。校验通过显示“哈希链完整”；发现问题时分别提示某条记录的内容与封存时不一致（可能被修改）、与前一条衔接不上（中间的记录可能被删除），或链尾不完整（最新的记录可能被删除）。一次没有校验到链尾时点击“继续校验”接着往后查。按保留期清理旧审计会留下锚点，不会被误报为断裂。

审计不记录明文密码、API Key、Webhook 密钥或 token，也不记录每次查询和权限校验。默认保留 180 天。哈希链能发现事后修改，但链条与数据在同一数据库中，不能代替导出到外部 SIEM 或 WORM 存储的合规存证。

### 6.12 系统状态

集中显示运行时（版本、运行时长、Java 版本、数据库连接与延迟、缓存状态）、数据规模（用户、部门、软件、角色与权限、角色分配）、待处理事项（待审批申请、进行中的复核、7 天内到期的授权、Webhook 待投递）以及审计链封存进度。用于日常巡检，指标采集仍以监控端口 8081 为准。数据库不可用时页面顶部提示“数据库不可用”，数据规模、待处理事项和审计链显示为“—”或“暂时无法读取”，恢复后点击“刷新”。

### 6.13 管理员账号（仅超级管理员）

创建、编辑、重置密码、解锁、重置两步验证和删除控制台管理员账号。创建时选择角色；软件管理员还需要选择可管理的软件。列表显示每个账号是否启用了两步验证。

不能修改自己的角色、停用或删除自己；平台至少保留一个启用的超级管理员。修改角色、停用或重置密码后，该账号的全部登录会话立即下线。账号名可以包含 `@` 和 `.`（例如邮箱形式），但不能以 `.` 开头。删除账号会同时结束其全部会话；之后用同一账号名重新创建的账号与旧账号无关，旧账号的会话和正在进行的登录都不能用于新账号。

### 6.14 接入指南

面向业务软件开发人员，分四个标签：

- **接入流程**：从接入软件、保存 API Key、定义权限和角色到每次操作前校验的完整步骤，以及“当前部门是全局的”等关键约定。
- **接口清单**：业务 API 的路径、用途和错误码。
- **代码示例**：可复制的 curl 示例和 Java（Spring Boot 3）示例。
- **在线调试**：输入一个测试用 API Key，真实调用创建上下文、校验权限、查询有效权限和注销上下文。注意创建上下文会真实切换该用户的当前部门；API Key 只保存在当前页面内存中，请只使用测试密钥。

## 七、从零建立完整授权链

以下名称和编码均为示例，不会由系统自动生成：

1. 在“部门”创建“研发部”（`development`）和“产品部”（`product`）。新建后可在自动打开的“部门成员”中维护人员。
2. 在研发部的“部门成员”新建“测试用户”，外部标识 `sample-user`，所属部门保留研发部并加选产品部。
3. 在“软件接入”创建“项目系统”（`project-system`），保存一次性显示的 API Key，关闭提示后进入软件配置抽屉，选择研发部。
4. 在“角色”页签新建“阅读者”（`reader`），自动进入权限配置弹窗。
5. 点击“新建权限并勾选”，创建 `project:read`（查看项目，资源 `project`，操作 `read`），返回后它已在“已授予”列表。
6. 点击“保存并分配成员”，搜索测试用户、添加并保存。多人多软件授权也可在同一配置抽屉的“成员授权”中完成。
7. 在“权限诊断”选择测试用户、研发部、项目系统，校验 `project:read` 和 `project:create`：前者允许，后者拒绝。
8. 在“接入指南 → 在线调试”填入 API Key，为 `sample-user` 在研发部创建上下文并校验，结果应与诊断一致。
9. 在项目系统配置抽屉点击“复制到多个部门”，来源选研发部、目标选产品部，完成后切换到产品部，另行分配成员角色。随后在在线调试中为同一用户切换到产品部，结果只反映产品部配置。
10. 用研发部的旧 token 再次校验，应返回 `CONTEXT_INVALID`；切回研发部后旧 token 仍然无效，必须使用新创建的 token。

如果没有给用户分配角色，或角色没有关联权限，用户权限为空，而不是自动允许。验证后可在控制台逐项清理示例数据：先删除角色和权限，再把用户移出部门或删除用户，最后删除软件和部门。删除被拒绝时，按提示中列出的剩余内容逐项清理。

## 八、业务软件如何接入

业务软件后端保存自己的 API Key，完成用户登录认证后，用可信的 externalId 与目标 departmentId 创建上下文。随后在每次受保护操作之前，把所需权限编码交给平台检查，只有整体允许时才执行业务。

- 收到 `CONTEXT_INVALID` 时重新为用户当前部门创建上下文，不能沿用旧 token。
- 收到 429 或 503 时按 `Retry-After` 退避重试。
- 未知权限、鉴权失败、网络故障一律按拒绝处理。
- 可以代员工提交角色申请、查询申请状态和撤回待审批申请，也可以只读查询员工当前在某部门的角色与权限（不切换部门）。
- 建议登记 Webhook：收到用户停用、角色变更、审批结果等事件后清理本地缓存或会话。必须先验签再处理。

Java（Spring Boot）项目可以直接使用 `sdk/java` 中的 `melonhub-client`：配置 `melonhub.client.base-url` 和 `melonhub.client.api-key` 后自动装配，在控制器方法上加 `@RequirePermission("item:read")` 即可校验；SDK 负责上下文缓存与重建、429/503 退避、平台故障时拒绝（fail-closed）以及 Webhook 验签。安装与用法见 [SDK 说明](../sdk/java/README.md)。

业务后端也可以通过本软件的 API 管理角色、权限和分配关系；用户身份和部门成员关系由平台管理员维护。路径、请求体和错误码见 [接口说明](API.md)。

## 九、常见问题

| 现象 | 处理方式 |
| --- | --- |
| 页面可打开但显示“数据库不可用” | 检查 Docker Desktop 与 MySQL 容器，查看 `.local/logs/backend.log` |
| 顶部显示“缓存降级” | Redis 不可用或刚恢复；授权仍正确但变慢，限流退回按实例计算。检查 `melonhub-redis` 容器，恢复后几秒内自动转为正常 |
| 一键启动提示 `REDIS_PASSWORD must be configured` | 在 `.env` 中填写自行生成的 Redis 密码，或设 `CACHE_ENABLED=false` |
| 一键启动提示 8080 或 5174 被占用 | 停止已确认属于本项目的旧实例；IDEA 实例在 Run/Debug 面板停止，不要结束全部 Java 进程 |
| 登录提示账号已锁定 | 等待 15 分钟，或请超级管理员在“管理员账号”中解锁 |
| 登录要求输入动态口令，但认证器丢失 | 请超级管理员在“管理员账号”中重置两步验证，登录后重新绑定 |
| 动态口令提示“不正确或已使用” | 确认手机时间准确；同一个口令只能登录一次，等待下一个口令 |
| 初始管理员忘记密码 | 在 `.env` 设置新的 `ADMIN_PASSWORD` 和 `ADMIN_PASSWORD_RESET=true`，重启后端登录，再改回 `false` |
| 看不到某个软件 | 软件管理员只能看到被授权的软件，请超级管理员调整授权 |
| 看不到角色或权限 | 打开部门或软件的配置抽屉，确认当前部门与软件正确，同名数据在其他授权域不会显示 |
| 用户无法分配角色 | 先在“用户”页把该用户加入当前部门 |
| 权限校验为 false | 用“权限诊断”逐项检查成员关系、角色分配（含是否到期）、角色启用、权限关联及编码大小写 |
| 返回 `CONTEXT_INVALID` | 用户切换部门、修改外部标识、角色重分配、审批通过、复核回收、停用、到期、注销或被强制下线；重新创建上下文 |
| 返回 429 `RATE_LIMITED` | 该软件超过每秒调用上限；业务侧应退避重试，确有需要可在“软件接入 → 更多 → 限流”调整，或修改 `APP_RATE_LIMIT` |
| 返回 503 `SERVICE_BUSY` | 数据库连接池耗尽或锁等待超时，按 `Retry-After` 重试并检查数据库负载 |
| 删除失败并返回 CONFLICT | 提示会写明仍有多少成员、角色或权限；先处理这些关联，不要关闭外键或删库 |
| Webhook 一直显示待投递或失败 | 在“投递记录”查看最后的 HTTP 状态与错误；确认接收地址可达、返回 2xx、验签使用原始请求体 |
