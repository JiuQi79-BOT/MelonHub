# MelonHub 项目使用说明书

本文说明项目的用途、启停方式、各页面的功能以及从零建立一条授权链的步骤。接口细节见 [业务 API 说明](API.md)，技术分层与权限规则见 [架构说明](ARCHITECTURE.md)。

## 一、项目解决什么问题

MelonHub 是企业内部统一权限平台，为多个业务软件提供一致的角色、权限配置和在线授权判断。平台回答的是“某用户在某部门、某软件中有没有指定权限”，具体业务操作仍由业务软件执行。

例如，同一位用户在研发部门的项目系统中可以创建项目，在产品部门的同一系统中只能查看项目。两个部门即使都有名为“负责人”的角色，角色关联和权限也各自独立。

本项目严格使用 RBAC0：

```text
用户 ──分配──> 角色 ──关联──> 权限
          所有角色和权限均属于某个“部门 × 软件”隔离域
```

用户可以拥有多个角色，角色可以关联多个权限；有效权限取并集。用户不能直接获得权限，没有角色继承、通配权限或额外业务规则。

## 二、运行组成与准备工作

| 组成 | 运行位置 | 作用 |
| --- | --- | --- |
| Vue 管理控制台 | 本机，固定 5174 | 管理配置、查看审计及接口联调 |
| Spring Boot 后端 | 本机，8080 | 管理 API、身份凭据和在线权限判断 |
| MySQL | 现有华为云 Swarm | 持久化配置、授权关联、上下文和审计 |

前端通过本机 `/api` 代理请求后端，后端通过 TLS 连接云端 MySQL。项目不需要本机 MySQL。云服务器必须已开机、现有 MySQL 服务可用且网络可达；本地启停脚本不负责开关 ECS、部署 Swarm 或重启云端数据库。

本机需要 JDK（推荐 Java 21，源码目标 Java 17）、Maven、Node.js/npm 和 PowerShell。现有本机环境已具备这些工具。

根目录 `.env` 保存真实数据库地址、数据库凭据和管理员账号。新环境从 `.env.example` 补齐配置，不要把真实凭据写进 README、说明书、截图或命令参数。

| 关键配置 | 要求 |
| --- | --- |
| `SPRING_PROFILES_ACTIVE` | `cloud` |
| `CLOUD_DB_NAME` | `melonhub_rbac` |
| `CLOUD_DB_HOST/PORT/USERNAME/PASSWORD` | 已验证的云端连接信息 |
| `ADMIN_USERNAME/ADMIN_PASSWORD` | 控制台管理员；密码至少 12 位 |
| `SERVER_PORT` | `8080`，与前端代理保持一致 |
| `SEED_DEMO` | `false`，云端不自动生成演示数据 |
| `TEST_DB_URL/USERNAME/PASSWORD` | 仅用于云端独立测试库 `melonhub_rbac_test` |

SSH 密码与 MySQL 密码用途不同；启动项目只需要数据库凭据，不需要先登录服务器终端。

## 三、一键启动和停止

### 3.1 双击启动

双击根目录的 `start-all.cmd`。脚本会读取配置，必要时构建后端或安装缺失的前端依赖，然后在后台启动本项目前后端，等待后端、数据库与前端代理均健康后打开浏览器。

固定访问 `http://127.0.0.1:5174`；一键脚本、命令行和 IDEA 的前端运行配置均使用该端口。5174 或后端 8080 被其他程序占用时会报错，不会停止该程序或自动切换端口。5173 留给其他项目使用。

已运行且健康的项目进程会被复用，重复双击不会再开一套服务。修改代码或连接配置后，应先停止再启动，使新配置生效。

命令行也可以运行：

```powershell
./scripts/start-all.ps1
./scripts/start-all.ps1 -NoBrowser
./scripts/start-all.ps1 -Rebuild
```

`-NoBrowser` 只启动并检查服务，不自动打开页面；`-Rebuild` 强制重新打包后端，使用前先停止正在运行的后端。启动成功会把实际地址记录在忽略文件 `.local/services.json`。

### 3.2 双击停止

双击根目录 `stop-all.cmd`，或执行：

```powershell
./scripts/stop-all.ps1
```

停止脚本按本项目绝对路径识别 JAR、Vite 和可识别的 IDEA 后端进程，不使用“停止全部 Java/Node 进程”的方式。重复停止是安全的；云端 MySQL、其他项目和本机 MySQL均不会被停止。

IDEA 若通过不含项目路径的临时参数文件运行，脚本可能无法确认归属；此时应在 IDEA Run/Debug 面板停止该进程。8080 仍被占用时，先确认占用者再操作。

关闭网页不会停止服务。后台运行日志在 `.local/logs/backend.log` 和 `.local/logs/frontend.log`，启动器会屏蔽已配置的密码和服务器地址。分享日志前仍需核对内容。

### 3.3 云数据库连接何时建立与断开

启动后端时，Hikari 连接池会建立到云端 MySQL 的连接；启动脚本须确认数据库健康才报告启动成功。停止后端时，这个进程的数据库连接会释放。连接数不一定等于 1，因为连接池会维护多个可复用连接。

本轮通过云端 MySQL 只读查看项目库连接数，实测为：**启动后 10 条 → 停止后 0 条 → 再次启动后恢复 10 条**。这里管理的是应用连接，停止不会删除数据、删除数据库或关闭云端 MySQL，其他应用可以继续使用数据库服务。

### 3.4 在 IDEA 中调试

1. 在 IDEA 打开项目根目录并导入根 `pom.xml`。
2. SDK 推荐选择本机 `D:\jdk21`。
3. 选择 `MelonHub Backend` 启动/调试后端，选择 `MelonHub Frontend` 启动 Vite。
4. 支持 npm 的 IDEA 可以用 `MelonHub Stack` 同时启动；`MelonHub Tests` 执行独立云端测试。
5. 在 Run/Debug 面板管理停止和重启。切换运行方式前先停止旧实例，避免 8080 冲突。

共享配置位于 `.run/`。本轮实际服务启停验证使用一键脚本完成，未把 IDEA 图形界面启动当作已验证事实。

## 四、登录与隔离域选择

启动后使用 `.env` 的管理员账号、密码登录。管理员会话有效期为 8 小时，过期后重新登录。点击右上角账号菜单可以退出；退出只注销当前管理员会话，不停止服务。

页面顶部的“当前部门”和“当前软件”选择的是**管理界面的隔离域**，决定角色、权限及分配关系的查看范围。它不会直接切换某个业务用户的全局当前部门。

业务用户真正的部门切换发生在创建权限上下文时：API 联调页的“创建上下文 / 切换部门”，或业务接口 `POST /api/v1/contexts`。这两种“切换”不要混淆。

云端关闭演示数据，因此初次进入时可能没有部门或软件。先创建它们，再配置角色和权限；空列表本身不代表连接失败。

## 五、各页面的功能和目的

### 5.1 权限概览

展示接入软件数、部门数、用户数、有效上下文，以及当前隔离域的角色、权限、授权人数和最近操作。用于确认平台规模和当前域授权状态。

顶部部分数字是平台总量，角色、权限和授权人数随当前隔离域变化。概览中的软件列表可切换管理目标，刷新按钮用于重新读取服务数据。

### 5.2 软件管理

一个“软件”表示一个独立接入的业务系统，例如项目系统、报销系统。创建时填写名称、唯一编码和可选描述。

创建成功后会显示一次 API Key，交给该软件的可信后端保存。列表不会再次显示原 Key；遗失时通过更多操作重置，并同步更新业务后端配置。原 Key 在重置后立即失效。

“管理”进入该软件的角色页面；编辑修改说明信息；停用会阻止该软件继续使用其凭据并清除其上下文；删除仍受数据库关联依赖限制。

### 5.3 部门管理

维护组织部门名称与唯一编码，查看成员数量。部门是权限隔离的一个维度，不是角色继承层级。

创建部门不会自动创建角色、权限或成员。成员关系在用户编辑中维护。存在成员、角色、权限或上下文等依赖时，不能直接删除部门，应先处理相关关系。

### 5.4 用户管理

维护姓名、用户标识 `externalId`、可选邮箱和归属部门。用户标识用于业务后端对接，须与业务系统认证后的用户身份对应。

一个用户可以勾选多个部门。加入部门仅获得成员身份，不会自动获得该部门任何软件的权限。

选好顶部部门和软件后，点击该用户的“分配角色”，勾选本域角色并保存。列表是整体替换，取消勾选表示移除相应角色。用户必须是当前部门成员才能分配。

用户编辑、归属变化和角色重新分配会使其相关旧上下文失效。停用用户后不能继续使用权限上下文；重新启用也须重新创建上下文。

### 5.5 角色管理

角色属于顶部选定的“部门 × 软件”，用于把一组权限打包给用户。填写角色名称、域内唯一编码和可选描述。

点击“配置权限”，勾选当前域中已有权限，再保存授权。该操作整体替换角色权限集合，清空选择即可移除全部权限。同名角色在不同部门或软件中互不关联。

角色停用后，下一次实时校验不再计入该角色权限。删除角色会移除其相关分配与权限关联，不会删除用户或其他角色。

### 5.6 权限管理

维护权限名称、唯一编码、资源标识和操作标识。例如“查看项目”可用 `project:read`，“创建项目”可用 `project:create`。

权限编码区分大小写，平台只把它当作标识，不会根据 `read`、`create`、冒号或 resource/action 自动推导额外权限。业务后端检查的编码必须与这里完全一致。

创建权限后还要关联给角色，再把角色分配给用户，授权链才完整。删除权限会移除相关角色权限关系，已有上下文下一次校验便不能继续获得该权限。

### 5.7 审计日志

查看谁在何时创建、编辑、删除或调整了授权配置，以及上下文的创建等操作。支持搜索、域筛选及 CSV 导出，适合排查授权变更。

审计不会记录明文密码、API Key 或 token，不记录每次查询和权限校验；它是项目操作记录，不是不可篡改的合规存证。删除临时业务数据后，其审计记录仍会保留，历史关联名称可能为空。

### 5.8 API 联调

用于验证“用户身份 → 部门 → 软件 → 有效权限”的结果。它有权限上下文、接口参考、请求示例三个标签。

管理员联调使用当前登录会话和顶部软件；软件 API 模式使用输入的 API Key，实际软件身份由 Key 决定。该页面仅供可信平台管理员调试，不表示可以把 Key 放进普通用户端。

选择用户和目标部门，点击“创建上下文 / 切换部门”，响应会包含新的 token 和权限。填写待校验权限，点击“执行校验”；多项以英文逗号分隔。也可以查询当前有效角色与权限，或选择历史上下文验证其是否失效。

同一用户切换到其他部门后，其原部门在所有软件、所有设备中的旧上下文都会失效；切回原部门也不会恢复。当前产品采用用户全局当前部门，不是每个设备独立的部门选择。

## 六、从零建立完整授权链

以下名称和编码均为示例，不会由系统自动生成：

1. 在部门管理创建“研发部”，编码 `development`；另建“产品部”，编码 `product`。
2. 在软件管理创建“项目系统”，编码 `project-system`，记录一次性 API Key。
3. 在用户管理创建“测试用户”，用户标识 `sample-user`，同时勾选两个部门。
4. 顶部选择“研发部 / 项目系统”，在权限管理创建“查看项目”，编码 `project:read`，资源 `project`，操作 `read`。
5. 在角色管理创建“阅读者”，编码 `reader`，配置其权限为“查看项目”。
6. 在用户管理给测试用户分配当前域的“阅读者”。
7. 在 API 联调选择该用户与研发部，创建上下文，校验 `project:read`，应得到 `allowed=true`。
8. 将待校验内容改为 `project:read, project:create`，若未授予创建权限，应得到 read 为 true、create 为 false，整体 allowed 为 false。
9. 为产品部另建角色、权限及用户角色关系，随后在联调页为同一用户切换到产品部。结果应只反映产品部配置。
10. 选择研发部的历史上下文重新校验，应返回 `CONTEXT_INVALID`；切回研发部后，该历史 token 仍然无效，须使用新创建的 token。

如果没有给用户分配角色，或角色没有关联权限，用户权限应为空，而不是自动允许。验证后可通过控制台逐项清理示例数据；删除用户会清理其成员及上下文关系，角色和权限删除后再删除软件与部门。

## 七、业务软件如何接入

业务软件后端保存自己的 API Key，完成用户登录认证后，使用可信 externalId 与目标 departmentId 创建上下文。随后在每次受保护业务操作之前，把该操作所需权限编码交给平台检查。

只有整体允许时才执行业务。收到上下文无效应重新建立用户当前部门的上下文，不能继续沿用旧 token；遇到未知权限、鉴权失败或网络故障，不应默认为有权限。

业务后端可以通过本软件 API 管理角色、权限和分配关系；用户身份和部门成员关系由平台管理员维护。具体路径、请求体和错误码见 [业务 API 说明](API.md)。

## 八、常见问题

| 现象 | 处理方式 |
| --- | --- |
| 页面可打开但显示服务异常 | 检查后端健康接口和 `.local/logs/backend.log`；前端页面可用不代表云数据库已连通 |
| 一键启动提示 8080 被占用 | 停止已确认属于本项目的旧实例；IDEA 实例优先在 Run/Debug 面板停止，不要结束全部 Java 进程 |
| 前端 5174 无法打开 | 查看启动器输出，确认服务已启动；端口被占用时先处理冲突，不会自动顺延 |
| 云端连接超时 | 确认 ECS 已开机、入口和访问规则可达；超时发生在认证前，不能据此判断密码错误 |
| 数据库认证失败 | 核对 `.env` 的 MySQL 凭据；SSH 密码不是数据库密码 |
| 登录失败 | 核对 ADMIN 配置；管理员密码至少 12 位；启动后变更 `.env` 需重启后端 |
| 看不到角色或权限 | 确认顶部部门与软件正确，同名数据在其他域不会自动显示 |
| 用户无法分配角色 | 先确认该用户属于当前部门，并已选择软件 |
| 权限校验为 false | 检查成员 → 本域角色 → 启用状态 → 权限关联及编码大小写；未知权限一律为 false |
| 返回 CONTEXT_INVALID | 用户切换部门、编辑、角色重分配、停用、到期或注销均可能导致；重新创建上下文 |
| 删除失败并返回 CONFLICT | 仍有成员、角色、权限或上下文依赖，先处理关联，不要直接关闭外键或删库 |
| MySQL 9.2 的 Flyway 警告 | 当前迁移及项目用例已通过；警告仍存在，后续升级 Flyway 时再验证完整兼容性 |

审计时间和会话过期已通过连接端时区修正：驱动读取数据库实际时区，不改 Linux 或 MySQL 全局设置。

## 九、验证与维护

```powershell
./scripts/check-cloud-database.ps1
./scripts/test-backend.ps1
npm --prefix frontend run build
```

第一项只读检查网络、TLS、认证与库是否存在；第二项只允许云端独立测试库，错误目标会在连接和迁移前被拒绝，不会回退到本机；第三项检查前端类型并生成生产构建。

2026-10-18 已通过 25 项后端测试（16 项集成、9 项保护），零失败、零错误、零跳过；还通过浏览器配置和授权、跨部门旧 token 失效、页面刷新、桌面/移动页面和直接云端 SQL 回读验证。验证数据已清理，审计保留。

正式运行前端和后端不需要每次跑集成测试。修改源码、配置或依赖后重新构建/重启，再根据变更范围验证。不要执行实验 SQL、重新初始化已有 MySQL 或修改其他应用数据库。
