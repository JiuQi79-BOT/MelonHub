# 搜索竞态修复验证

验证日期：2026-10-20，UTC+8。本轮基于上游 `main`，独立于尚未合并的 PR #2；仅修改两个前端组件、组件回归测试和文档，无后端、SDK、数据库迁移或依赖变更。

## 复现与修复

### 全局搜索的旧结果回填

原来仅在 300 毫秒防抖结束、发起请求时增加请求序号。因此用户清空输入、在手机上取消搜索、选中结果，或输入新关键词但还在防抖期间，旧请求仍可回填结果；取消或选中也不会清理待执行的定时器。

现在在每次输入变化时立即使旧请求失效、清除旧结果并更新加载状态。取消和选中结果复用清空搜索的流程，停止定时器并使在途响应失效；卸载时同样丢弃在途响应。选中用户时先保存当前查询结果，再清空搜索，仍携带正确的外部标识跳转。

### 选人器的过时查询与跨部门定时器

原来同样在 250 毫秒防抖结束后才增加序号，旧请求可在新输入等待期间回填成员。切换部门虽然会立即查询新部门，但没有取消原搜索定时器；该定时器随后使用旧关键词查询新部门，覆盖刚加载的新部门成员。

现在输入时立即使旧请求失效；切换部门取消旧定时器并清空旧列表，再加载新部门。保留已选用户的标签缓存，跨搜索选人及已选成员显示继续可用。

## 验证结果

- 修复前，首批 7 项组件用例中 **6 项预期失败、1 项通过**，复现旧响应回填、取消后仍请求、选中后仍请求和跨部门定时器。
- 修复后，新增 **8 项组件回归测试**及原有 **1 项会话竞态测试**共 **9 项通过**，无失败、取消或跳过。覆盖清空、手机取消、选中导航、新关键词防抖、切换部门和已选成员标签保留。
- 用例编译真实 Vue 单文件组件的 `script setup`，通过 Vue 渲染器运行响应式状态、监听器及挂载/卸载逻辑；使用可控时钟和延迟响应稳定复现竞态。测试桩替代 HTTP 和 UI 库渲染，未替换组件的搜索逻辑。
- `npm run build` 中的 `vue-tsc -b` 与 Vite 生产构建通过；`git diff --check` 通过。
