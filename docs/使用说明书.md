# MelonHub 功能演示操作手册

更新日期：2026-10-27。本手册供演示者照着操作：每个场景给出入口、填写内容、预期结果和恢复方法。第一次建议按顺序演练，正式展示时选择其中的主线。

## 1. 先让系统有东西可以演示

### 1.1 为什么管理员登录后是空的

2026-10-27 实际检查：当前账号为超级管理员，数据库正常，但正式运行环境中的部门、软件、用户、角色、权限均为 0。管理员账号只是控制台的管理身份，不会自动生成员工或业务配置；当前启动方式也关闭了自动示例数据。

已通过现有接口为当前运行环境准备下表中的演示数据。**刷新浏览器页面**，打开侧栏“部门”“软件接入”“用户”即可看到。角色与权限项的入口在软件配置抽屉中，操作见第 2 节。

如果是在另一套空环境中演示，先双击根目录 `start-all.cmd`，等启动成功，在项目根目录的 PowerShell 执行一次：

```powershell
node scripts/prepare-demo.cjs
```

此命令需要已安装 Node.js、本机 8080 API 通道可用，以及忽略文件 `.env` 中的管理员凭据与当前账号一致。它会向**当前连接的运行环境**写入演示数据，不是向自动化测试库写入，仅用于你准备展示的环境。

启动后访问 `http://127.0.0.1:5174`，使用现有管理员账号登录即可。停止本机演示时双击 `stop-all.cmd`；演示数据保留，服务器后端继续运行。

准备工具按演示编码查找并补建缺失对象，补充基准角色，不清空已有数据，不重置已完成的审批、不覆盖已修改的角色权限或已有有效分配期限。重复运行也不会把演示恢复到初始状态；重演前按第 11 节检查。临时验证密钥会自动吊销，不输出真实凭据。

5. 第 6 节：复核回收创建角色，验证重新拒绝，约 3 分钟。
6. 第 9 节：展示审计记录与链条校验，约 2 分钟。

第 7、8、10 节可按展示重点追加。开场可先说：“我们以研发部李四需要创建项目为例，走完申请、授权、验证和回收。”

## 2. 找到角色、权限，并演示如何配置

### 2.1 打开现成配置

1. 登录后，点击侧栏“软件接入”。
2. 找到“演示·项目协作”，点击**软件名称**，打开“软件配置”抽屉。
3. 抽屉顶部“成员筛选”选“全部成员”。部门筛选只决定看哪些人。
4. 点“角色”标签，应看到项目查看员、项目创建员、项目审批员。
5. 点项目创建员这一行的“配置权限”。左侧是可选权限，右侧“已授予”应有 `project:read` 和 `project:create`。
6. 关闭弹窗，点“权限项”标签，应看到 3 条权限定义。`project:read` 只定义一次，可以同时授予三个角色。

可以这样讲：“先在软件里定义能做的事，再把这些事组合成岗位角色，最后把角色分配给员工。”

### 2.2 现场新增一个角色

使用独立练习角色，避免打乱后续主线。

1. 回到“角色”，点“新建角色”。
2. 角色名称填“演示观察员”，编码填 `observer-demo`，描述填“现场演示创建角色”，点“保存”。
3. 在随后出现的角色权限弹窗中，勾选左侧 `project:read`，点中间向右箭头，将它移入“已授予”。如弹窗没有自动打开，点新角色这一行的“配置权限”。
4. 点“保存”，角色行权限数量应为 1。
5. 需要现场新建权限时，点“新建权限并勾选”，填写名称“导出项目”、编码 `project:export`、资源 `project`、动作 `export`。保存后再保存角色权限。

预期：没有分配这个角色的人，不会因为你创建了角色就自动获得权限。需要时到“成员授权”单独分配给练习用户。

演示后，在该角色“更多 → 删除”中删除练习角色；如创建过 `project:export`，再到“权限项”删除它。不要删除主线中的三个角色。

### 2.3 如果要完全从零配置

1. “部门 → 新建部门”：填名称和唯一编码，保存后进入部门配置。
2. “部门成员 → 新建用户”：填姓名、外部标识及所属部门。外部标识必须唯一，可用 `practice-xiaoming`，不用填写密码。
3. 关闭抽屉，到“软件接入 → 接入软件”：填软件名称、编码、负责人和描述。练习可用“练习项目系统”及 `practice-project`。
4. 保存后显示一次性 API Key，仅在本机妥善保存，不投影展示或提交到仓库；关闭后进入软件配置。
5. 在“角色”中新建角色，点“新建权限并勾选”，填权限名称、编码、资源、动作，再“保存并分配成员”。
6. 也可到“成员授权”，给刚才的用户分配角色，按第 3 节验证。

已有演示数据时无需重复创建同名对象；编码重复会被拒绝。

## 3. 先证明谁能创建项目，谁不能

这一步不需要 API Key，也不用写请求，适合第一次演练。

1. 关闭配置抽屉，点击侧栏“权限诊断”。
2. “用户”搜索并选择“演示·张三”；“软件”选“演示·项目协作”。
3. 部门可留空；“激活角色”选“全部已分配角色”。
4. “待校验权限”依次填 `project:read`、`project:create`、`project:approve`，每项输入后按回车。
5. 点“开始诊断”。预期查看和创建为允许，审批为拒绝，总体“未全部通过”。总体表示填写的权限是否**全部**满足，并不代表所有操作都被拒绝。
6. 用户改为李四，再点“开始诊断”。预期只有查看允许，创建和审批均拒绝。
7. 用户改为王五，再次诊断。预期查看和审批允许，创建拒绝。

可以这样讲：“岗位不同，权限不同。这里能解释每个权限来自哪个角色；业务系统也会通过接口得到同样的允许或拒绝结果。”

附加演示：选择赵六，部门留空，检查 `project:read`，应允许。说明员工可以不属于任何部门，软件角色仍然有效。

## 4. 如何管理研发部成员的软件权限

目标：从部门入口选人，给研发部成员设置项目协作权限。

### 4.1 按部门批量授权

1. 点击侧栏“部门”，找到“演示·研发部”，点该行的“软件与授权”。
2. 抽屉顶部“配置软件”选“演示·项目协作”。
3. 点“成员授权”。预期只显示张三和李四；赵六不在研发部，所以不出现在这里。
4. 勾选张三和李四，点“批量分配软件角色”。
5. 在弹窗中选择“演示·项目协作”，勾选项目查看员。新增分配的有效天数留空，点“追加角色”。
6. 关闭弹窗后检查：李四仍有项目查看员，张三在原项目创建员之外增加项目查看员。张三原角色和期限保留。

如要演示多软件授权，在第 5 步再选“演示·费用报销”，勾选它的报销申请人。各软件分别提交，成功的软件保留结果；提示部分失败时，检查未完成的软件再继续。这个扩展会让李四也能提交报销。

可以这样讲：“部门帮助我们一次选中一群人，再给这些人在某个软件里追加角色。”

### 4.2 单独调整李四

1. 在同一个“成员授权”表中，点李四的“个别调整”。
2. 保留项目查看员，再勾选项目创建员，点“保存”。
3. 关闭抽屉，到“权限诊断”，选择李四与项目协作，检查 `project:create`，应变成允许。
4. 回到研发部配置抽屉，给李四再次“个别调整”，**只保留项目查看员**并保存。
5. 再次诊断创建权限，应恢复拒绝。做完这一步再进入下一节审批演示。

注意：个别调整保存的是用户在当前软件的**完整角色集合**。取消某角色就会撤销它；全部清空则撤销该软件全部角色。需要保留的角色必须继续勾选。

### 4.3 调部门和撤授权如何分别操作

调整所属部门：进入侧栏“用户”，点用户“编辑”，修改“所属部门”后保存。撤销软件权限：进入“成员授权”，取消对应软件角色后保存。

只把李四移出研发部，不会撤销他已有的软件角色。此时研发部筛选下不再显示李四，但软件配置中选择“全部成员”仍能找到他。演示后请把李四重新加入研发部，方便后续复核按部门筛选。

同样，编辑某角色的权限会影响软件中**所有拥有该角色的员工**。只想调整李四时，应调整李四的角色分配；不要直接改共享角色的权限集合。

## 5. 员工申请 → 管理员批准 → 权限生效

准备工具已通过业务接口替李四提交一条申请。“审批中心”负责处理申请；员工发起申请来自业务软件，控制台没有员工申请页面。

1. 先按第 3 节确认李四的 `project:create` 为拒绝。
2. 打开“审批中心”，软件选“演示·项目协作”，状态选待审批，清空搜索条件。
3. 找到“演示·李四 → 项目创建员”，理由为“演示：李四需要创建项目，请授予 7 天项目创建员角色”。
4. 点“批准”，选择“指定天数”并填 7，备注填“演示审批通过”，点“批准”确认。也可以直接选择“按申请（7 天）”。
5. 状态变为已批准，并显示决定人、备注和到期时间。如还筛选着待审批，这一行会消失，切到全部状态查看。
6. 到“权限诊断”，用李四校验 `project:read` 和 `project:create`，应均允许。
7. 回到软件配置的“成员授权”，应看到李四的项目创建员及到期时间；“即将到期”标签中可选 15 天内查看。

可以这样讲：“申请本身不给权限，管理员批准后才授予角色，还可以限定只用 7 天。”

如要演示驳回，先恢复李四仅有项目查看员，执行下列命令重新提交申请，再在审批中心点“驳回”并填写理由。预期角色没有增加、创建权限仍拒绝。

```powershell
node scripts/prepare-demo.cjs --request
```

已有待审批时命令保留原申请。李四已有创建员角色时不会重复申请，按第 11 节先恢复。命令使用临时业务密钥提交请求，结束后吊销。

## 6. 权限复核 → 回收授权 → 再次拒绝

先完成第 5 节，使李四同时有项目查看员和项目创建员。

1. 点击“权限复核 → 发起复核”。
2. 复核名称填“演示·研发部项目权限复核”，软件选项目协作，部门选研发部，截止天数填 7，点“发起”。
3. 找到刚创建的复核，点“处理”，打开明细。
4. 在李四的**项目查看员**这一条点“保留”，备注填“保留基础查看”，保存。
5. 在李四的**项目创建员**这一条点“回收”，备注填“演示工作完成”，保存，暂时不要关闭复核。
6. 此时用另一个标签页进入权限诊断：李四创建权限仍允许，标记结论尚未实际回收。
7. 回到复核明细，点右上角“关闭并应用”，检查回收对象并确认。
8. 再次诊断：李四仍可查看项目，创建项目应变成拒绝。复核明细显示已关闭、对应条目已回收。

其他条目可以标记保留；未决条目在关闭时也按保留处理。关闭后不能重新编辑结论，重演需新建一次复核。复核期间如对同一分配重新授权或续期，旧复核回收会跳过它；为了演示上述效果，标记后不要再改李四的角色或期限。

## 7. 演示临时授权自动到期

1. 进入“演示·项目协作 → 成员授权”，成员筛选选全部成员。
2. 找到无部门的赵六，点“个别调整”。保留项目查看员，新增勾选项目创建员。
3. 在项目创建员这一行的日期时间选择器中，选距当前约 **3 分钟后**的时间；项目查看员留空表示永久，点“保存”。
4. 到权限诊断，赵六的 `project:create` 应允许；“即将到期”列表出现临时分配。
5. 到指定时间后，再点“开始诊断”，创建权限应拒绝，查看仍允许。不要只看屏幕上上一次诊断留下的结果。
6. 约一分钟内后台清理任务删除到期分配并写角色到期审计；权限判断从到期时刻就不再计算这个角色，无需等清理。

演示后检查赵六只保留永久项目查看员。若还没到期，可在“个别调整”取消项目创建员。不要用已过去的时间保存，表单会拒绝。

## 8. 通过真实 API 验证权限

“权限诊断”是管理员预演；这里展示业务软件如何调用真实业务接口。使用“在线调试”，无需手写请求。

1. 到“软件接入”，在“演示·项目协作”一行点“API Key → 新建密钥”。名称填“现场演示临时密钥”，选 30 天有效期，点“创建”。
2. 在一次性密钥弹窗复制密钥，暂存在自己本机，不展示给观众。
3. 打开“接入指南 → 在线调试”，把密钥填入 `X-API-Key`，外部标识填 `demo-lisi`，来源部门可留空。
4. 点“创建上下文”。预期 HTTP 200，`X-Context-Token` 自动填入。它代表后端接下来要检查的员工及其当前软件角色。
5. “待校验权限”输入 `project:read`、`project:create`，逐项回车，点“校验权限”。
6. 如已完成复核，预期查看为 true、创建为 false，整体 `allowed` 为 false；如李四尚持有项目创建员，两项均 true。HTTP 200 说明检查请求处理成功，业务是否允许看 `allowed` 和逐项结果。
7. 点“查询有效权限”，查看实际生效角色及权限。然后点“注销上下文”，再校验应提示上下文失效。
8. 结束后回到 API Key 列表，仅吊销刚创建的“现场演示临时密钥”。离开在线调试页会清除页面内存中的密钥和 token；剪贴板或手动记录需自己清理。

如在第 4 步后另开标签页调整李四角色，已有上下文失效；再校验出现 `CONTEXT_INVALID` 是预期结果，重新点“创建上下文”后再校验。调整角色权限集合则在下一次校验按新集合判断。

可以这样讲：“业务系统先确认员工身份，把外部标识交给 MelonHub，之后每次创建项目前检查 `project:create`。MelonHub 返回允许，业务系统才执行自己的创建项目代码。”

在线调试是管理员演示工具的例外入口。实际接入时 API Key 只存放在可信业务后端，不能放进普通员工使用的网页或客户端。`POST /contexts/check` 是提交一组待检查权限，不会创建项目或给员工授权。

## 9. 从审计中找出刚才谁改了权限

1. 打开“审计日志”，清空不必要的时间、操作、软件过滤条件，点“查询”。
2. 选择演示项目协作，查询本次角色分配、申请批准、复核关闭等管理记录。
3. 查看记录的操作人、对象、详情和发生时间；并非每次只读权限校验都生成一条管理审计。
4. 点“导出 CSV”，得到可用于展示的列表。
5. 点“校验链条 → 开始校验”。刚写入的日志可能尚未封存，等约 10 秒再查；如只完成一部分，点“继续校验”，直至完成。

预期：校验通过，能追溯刚才的管理操作。这是库内完整性校验，不是独立的外部公证。不要为了展示失败去手工篡改数据库。

## 10. 可选扩展演示

### 10.1 反查“谁能创建项目”

打开“演示·项目协作 → 权限项”，找到 `project:create`，点“使用者”。成员筛选选全部成员可查看软件中所有持有人；选研发部只看该部门成员。对照授权前后的李四是否出现，并查看他通过哪个角色获得权限。

### 10.2 配置导出和另一软件导入

1. 在“项目协作 → 角色”，点“权限清单 → 导出软件清单”，获得 v3 JSON。
2. 关闭抽屉，在软件接入创建“演示·配置副本”，编码 `demo-copy`。创建产生的 API Key 不用于本环节，结束后可吊销。
3. 打开副本软件“角色 → 权限清单 → 导入清单”，粘贴刚导出的 JSON，点“导入”。
4. 检查副本软件拥有相同角色和权限，但**没有自动复制员工的角色分配**。给用户分配副本软件角色后才能在副本中获得权限。

导入按编码新增或更新配置，并非完整备份恢复；不要向真实业务软件试导入。重演可继续用副本软件，编码相同的条目会更新。

### 10.3 批量导入用户

在“用户 → 批量导入”中粘贴下列内容并点“导入”：

```json
{"users":[{"name":"演示·钱七","externalId":"demo-qianqi","email":"","departmentCodes":["demo-rd"]}]}
```

预期新增钱七并加入研发部。重复导入按外部标识更新并补齐部门关系，不会新建第二个钱七。导入不自动授予软件角色，需按第 4 节授权。

### 10.4 分级管理员与 Webhook

分级管理员：超级管理员在“管理员账号 → 新建管理员”中，使用独立练习账号选择软件管理员并分配演示项目协作，再用独立无痕窗口登录。预期只能管理授权软件；不要在正式展示中改掉自己的超级管理员角色。结束后由原超级管理员停用练习账号。

Webhook 需要你拥有可接收请求的地址。准备好接收服务后，在演示软件的“Webhook”中新增订阅，设置接收地址、签名密钥和事件，保存后发送测试，查看投递结果；再调整一次演示用户角色，观察事件送达。未准备接收端时跳过本环节，不填任意外部地址。接收端应验签后处理，密钥不投影展示。

## 11. 重演前如何恢复，以及看不到数据怎么办

### 11.1 恢复演示起点

1. 在“项目协作 → 角色”检查三个主线角色启用且权限与第 1.2 节一致；如改过，点“配置权限”恢复勾选。
2. 成员筛选全部成员，用“个别调整”恢复：张三仅项目创建员、李四仅项目查看员、王五仅项目审批员、赵六仅项目查看员，均设永久。
3. 如演示过报销批量授权，在费用报销中恢复张三仅报销申请人；其他演示用户原本无报销角色，可取消本轮增加的角色。
4. 在“用户”中检查张三、李四在研发部，王五在财务部，赵六无部门，四人均启用；两款软件也应启用。
5. 执行 `node scripts/prepare-demo.cjs --request`，补李四的待审批申请。旧的已批准/驳回记录和已关闭复核保留，下一轮新建复核。
6. 吊销不用的现场演示密钥，清理自建练习角色/权限后，重做第 3 节诊断。

恢复后可运行：

```powershell
node scripts/prepare-demo.cjs --verify
```

它打印四个演示用户当前的允许/拒绝结果，并核对诊断与真实业务 API 是否一致。它不会把授权强制改成基准值，也不判断是否已恢复起点，需对照第 3 节自行检查。验证会短暂创建测试密钥和上下文，结束后清理。

本手册不会执行全库清空，演示数据持续保留供下次登录。需要移除时，先处理演示用户角色与练习角色，删除演示软件中的角色及权限后再删软件；用户移出部门后才能删部门。仅处理本轮演示对象，不处理真实业务配置。审批、复核和审计历史按系统保留规则保存。

### 11.2 刷新后仍然空白

| 现象 | 按顺序检查 |
| --- | --- |
| 部门、软件、用户全空 | 系统状态看数据库是否正常、数量是否为 0；另一套空环境运行准备命令；如接口报错，检查页面提示和本机 SSH API 通道 |
| 看不到角色/权限入口 | 软件接入 → 点软件名称 → 抽屉中的“角色”“权限项” |
| 抽屉只有部分人员或没人 | 软件抽屉成员筛选改全部成员；部门抽屉检查是否选错部门；清除表内搜索条件 |
| 审批中心找不到李四 | 软件选项目协作，清空状态/搜索；已批准的记录不在待审批中；重演按 11.1 补新申请 |
| 没有新增/保存按钮 | 检查账号身份；本手册按超级管理员演示，审计员只读，软件管理员仅能修改授权软件 |
| 密钥找不到原文 | 原文只显示一次；在演示软件中新建命名密钥，使用后单独吊销 |
| 结果与预期不同 | 确认软件、用户外部标识、激活角色、角色是否启用、分配是否到期；改授权后重新诊断，真实 API 重新创建上下文 |
| cache 显示 DISABLED | 当前默认关闭 Redis，正常走 MySQL，不影响本手册的功能演示 |

部署和账号恢复见 [服务器部署与启动](服务器部署与启动.md)，接口字段见 [API](API.md)，模型与表关系见 [数据库设计](数据库设计.md)。自动化测试与覆盖率使用独立云测试库，见 [JaCoCo 测试指南](JaCoCo测试指南.md)，不会替代本手册中的人工演示。
