# 服务器部署与启动

更新日期：2026-10-26。后端已部署到 `.env` 中工作节点对应的服务器，前端仍在本机运行。服务器地址和凭据仅保存在忽略的 `.env`，本文不列真实地址。

## 当前结构

```text
浏览器 http://127.0.0.1:5174
  → 本机 Vite /api 代理
  → 本机 127.0.0.1:8080 SSH 转发入口
  → 服务器 127.0.0.1:18080
  → melonhub-backend 容器的 8080
  → 云 MySQL melonhub_rbac
```

Java 后端实际在服务器运行，本机只有前端和 SSH 通道。服务器 API 仅发布到回环地址，通过 SSH 加密访问，不需要向公网开放后端端口。当前入口用于控制台及本机接入验证；其他业务服务器直接接入时应另配 HTTPS 入口及访问控制。

服务器使用独立容器 `melonhub-backend`，标签 `com.melonhub.role=backend`，512MiB 内存限制、256MiB 最大 Java 堆，非 root 用户和只读根文件系统。文件位于 `/opt/melonhub/`：配置 `.env` 权限为 600，运行包按 SHA-256 存放于 `releases/`，Docker 日志轮转。未修改其他应用的 8080 端口、容器、数据库或 Swarm 配置。Redis 仍关闭。

容器设置 `unless-stopped` 重启策略，服务器 Docker 已启用开机启动。已验证应用重启，未实际重启整台共享服务器。

## 每天使用

当前本机 `.env` 已设置 `BACKEND_MODE=server`。双击 `start-all.cmd`，或在项目根目录执行：

```powershell
./scripts/start-all.ps1 -NoBrowser
```

打开 `http://127.0.0.1:5174`，使用原有管理员账号登录，不需要重新初始化数据。

结束时双击 `stop-all.cmd`，或执行：

```powershell
./scripts/stop-all.ps1
```

停止的是本机前端和 SSH 通道，服务器后端继续运行。SSH 中断后重新启动本机项目即可；若本项目旧进程残留，先运行停止脚本，不要结束其他软件的进程。

## 管理服务器

以下命令在本机项目根目录执行，通过 `.env` 中的 SSH 配置管理本项目容器：

```powershell
./scripts/server-backend.ps1 status
./scripts/server-backend.ps1 restart
./scripts/server-backend.ps1 stop
./scripts/server-backend.ps1 start
```

`status` 返回运行状态、重启策略、运行包校验值和健康状态。`restart/start` 返回后应用可能还在初始化，可稍后查询 `status`。停止服务器后端会使控制台和业务 API 暂时不可用，本机 `stop-all` 不会执行这个操作。

可在服务器执行 `docker logs --tail 100 melonhub-backend` 排查问题。运行日志可能包含配置，不要公开上传原文。

## 修改代码后部署

先执行相应测试，再运行：

```powershell
./scripts/deploy-backend.ps1
./scripts/server-backend.ps1 status
```

脚本构建后端包、上传并验证 SHA-256，在相同服务器回环端口替换本项目容器。构建使用 `-DskipTests`，部署不能代替测试。新容器不健康时恢复旧容器；数据库迁移不会随容器自动回滚，新迁移部署前仍需备份。替换期间有短暂中断。

仅部署现有构建包时使用 `./scripts/deploy-backend.ps1 -SkipBuild`。服务器模式不能使用 `start-all -Rebuild`。前端源码由 Vite 加载，后端源码修改后必须重新部署才会生效。

服务器无法访问 Docker Hub，本次复用服务器已有、实测为 Java 21 的镜像，建立本项目标签 `melonhub-runtime:21`，由 `.env` 中的 `BACKEND_IMAGE` 指定。容器显式覆盖原镜像入口并使用独立 `/melonhub` 目录，原应用不会随之启动；运行时使用镜像 ID 固定。以后可换成可访问的官方 JRE 镜像再部署。

## 新电脑与开发模式

日常服务器模式需要 Node.js、Python 和 SSH 配置，不需要本机 Java/Maven。创建独立 Python 环境：

```powershell
python -m venv .local/cloud-tools
./.local/cloud-tools/Scripts/python.exe -m pip install -r scripts/requirements-server.txt
```

按 `.env.example` 创建忽略的 `.env`，设置 `BACKEND_MODE=server`、`BACKEND_REMOTE_PORT=18080` 和 `BACKEND_SSH_HOST/PORT/USERNAME/PASSWORD`。现有电脑沿用 `SWARM_WORKER_HOST` 与 `SWARM_SSH_*`，不会因此执行 Swarm 管理命令。首次连接固定 SSH 主机密钥，后续密钥变化会拒绝连接，不要直接删除已保存密钥以绕过错误。

本机编译、部署或测试才需要 Java/Maven；测试还需要独立云测试库配置。首次前端依赖安装执行 `npm --prefix frontend ci --ignore-scripts`。

需要在 IDEA 调试本机 Java 时，先停止本机项目，将 `.env` 中 `BACKEND_MODE` 改为 `local` 再启动。切回服务器模式同样先停再启，避免本机 Java 与 SSH 通道争用 8080。服务器后端不受本机模式切换影响。

本次已验证首次部署、再次替换部署、服务器应用重启、健康、前端代理、真实浏览器登录/概览/软件页面、本机停止不影响服务器及重复启动。标签保护、端口冲突保护和失败恢复由部署工具单元测试覆盖，见[验证记录](验证记录.md)。
